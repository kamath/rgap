RGAP is an authorization model for filesystem-like resources, tools, and
agent-accessible services. It supports hierarchical delegation, strict
downscoping, immediate revocation, and predictable access across resource
moves and renames.

<Callout type="info" title="The security invariant">
  Authority may only stay the same or become narrower as it is delegated. It
  can never expand.
</Callout>

## The model in one minute

RGAP separates three concerns:

| Concern | Purpose |
| --- | --- |
| **Resources** | Describe where objects live in a mutable hierarchy. |
| **Grants** | Describe where authority comes from and how it delegates. |
| **Tokens** | Provide opaque bearer credentials used to exercise a grant. |

```text
Resource tree                   Grant tree

acme/                           Company
├── platform/                   └── Platform team
│   ├── docs/                       └── Agent
│   └── tools/                          └── Sub-agent
└── finance/
```

A resource keeps the same stable identity when it moves. A grant carries one
or more capability entries over resource identities or paths. A child grant
can only narrow its parent's resources, permissions, constraints, and
expiration.

## Why RGAP

Agent runtimes often hold broad user authority while one execution needs a
small, auditable subset. Giving an agent the upstream OAuth token or API key
makes that boundary impossible to enforce.

RGAP lets a gateway retain provider credentials and issue an opaque token that
represents only the selected tools and resources. A sub-agent receives a new,
narrower token—not the parent token and never the provider credential.
