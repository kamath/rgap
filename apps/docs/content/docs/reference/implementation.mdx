The repository implements RGAP as framework-neutral TypeScript rules, durable
SQLite persistence, deployment-owned executable runtimes, a Hono HTTP server,
an executable scratchpad, and this MDX documentation application.

```text
packages/
├── core/           # authorization, executable orchestration, and contracts
└── sqlite/         # Drizzle and SQLite implementation
apps/
├── server/         # Hono HTTP API and generated clients
└── docs/           # Next.js and Fumadocs documentation
examples/
└── index.ts        # executable scratchpad
```

## Core boundary

`@rgap/core` separates five modules:

- `domain.ts` defines resources, grants, tokens, executable associations, audit
  events, permission algebra, and pure resource and grant rules.
- `repository.ts` defines `RgapCommands`, `RgapStore`, `RgapRepository`, and
  resource, grant, and token handles.
- `guard.ts` constructs the bearer-token command plane and enforces visibility
  and command authority.
- `executable.ts` atomically sets and deletes associations with sealed input
  bindings, records and revalidates binding authority, and orchestrates nested
  invocation.
- `runtime.ts` defines structural runtime schemas, typed invocations and
  results, invocation events, nested resource invocation, and `RuntimeRegistry`.

A store exposes only `as(token)` and `admin()`. Either method returns a
repository whose collections mint and look up handles.

Handles combine record fields with applicable commands:

- A resource creates descendants at a relative path, moves, deletes, manages
  its executable association, and invokes it.
- A grant creates descendants at a relative path, replaces resource entries,
  issues tokens, and revokes.
- A token revokes.

Adapters implement an ID-based `RgapCommands` sink.
`repositoryFrom(commands)` builds the handle surface. Resource and grant create
accept a slash-separated location and materialize missing prefixes. Path
rendering and grant-path resolution remain pure helpers.

### Repository planes

`store.as(token)` returns a guarded repository. Its commands authorize the
required permission before forwarding and reject with the decision detail.

`store.admin()` returns an unrestricted repository for trusted bootstrap and
operations code. Both planes share the same interface.

```ts
const repository = store.as(token);
const admin = store.admin();
```

### Reads

Focused collection queries list resources, grants, tokens, and audit events.
They return ordered arrays of serializable records with bounded page sizes and
keyset cursors. A caller never needs to load the complete store.

Ordinary commands are asynchronous and JSON-compatible. Invocation returns
`AsyncIterable<InvocationEvent>`, where events are `data` or `done`; runtime
failures terminate the iterable.

### TypeScript identities

The TypeScript surface brands identifiers that remain ordinary strings at
runtime and on the wire:

| Type | Used for |
| --- | --- |
| `ResourceId` | Resource records, grant-resource ID targets, and move destinations. |
| `GrantId` | Grant records, grant ancestry, and token grant references. |
| `TokenId` | Stored token-record identity. |
| `TokenValue` | The one-time bearer accepted by `store.as`, `authorize`, and `inspectToken`. |
| `TokenHash` | The bearer hash stored on a token record. |

Repository reads return branded values. Seed data and tests that construct
records directly use `resourceId`, `grantId`, `tokenId`, `tokenValue`, and
`tokenHash`. A path remains an ordinary string because it names a location
rather than a stable identity.

## Deployment-owned runtimes

The SQLite store accepts deployment-owned runtime configuration:

```ts
new SqliteRgapStore({
  url,
  runtimes,
});
```

Each heterogeneous `InvokeRuntime<TInput, TOutput>` owns nullable structural
input and output schemas and its invocation implementation. The schemas expose
`parse(value: unknown)`, so Zod schemas work directly without a core dependency
on Zod. Runtime registration and behavior are not repository state.

## SQLite store

`@rgap/sqlite` exports `SqliteRgapStore`. It accepts a file path or `:memory:`,
an optional initial state, and a runtime registry.

`src/schema.ts` declares normalized tables, and Drizzle Kit generates the DDL.
The constructor applies that DDL when it opens a database.

Each command runs in one `better-sqlite3` transaction:

1. Read the current state.
2. Apply the relevant pure core rule.
3. Replace persisted rows with the returned state.
4. Commit the state change and audit event together.

Rows are written parents before children so foreign keys hold after every
statement. Issued bearer values are returned once; token rows contain hashes.

The normalized schema stores one `executables` row per association, keyed by
`resource_id`, and one ordered `executable_bindings` row per sealed top-level
input field. Each binding stores the target resource ID and the grant lineage
that authorized `bind`, or administrative provenance. `setExecutable` verifies
that every resource is live and the runtime is registered, then atomically
replaces the association, bindings, and audit event. `deleteExecutable`
removes the association and its bindings and records the deletion. There is no
executable tombstone or revision table.

| Table | Contents |
| --- | --- |
| `resources` | Stable resource records and tombstones. |
| `grants` | Grant identity, ancestry, expiration, and revocation. |
| `grant_resources` | Ordered resource-ID or path targets for each grant. |
| `grant_resource_permissions` | Normalized permission sets for grant-resource entries. |
| `tokens` | Token metadata and bearer hashes. |
| `executables` | One resource-to-runtime association per executable resource. |
| `executable_bindings` | Resource IDs and authority lineages sealed into top-level input fields. |
| `audit` | Ordered authorization, mutation, and invocation events. |

## Invocation lifecycle

The token plane authorizes `invoke` on the executable resource. The
orchestrator then:

1. Resolves the executable association and registered runtime.
2. Revalidates every bound target and its recorded `bind` lineage.
3. Rejects caller values for sealed fields, inserts the bound resource ID
   strings, and parses the complete input when `inputSchema` is not null.
4. Calls the runtime with typed input, an `AbortSignal`, and nested invocation
   methods that accept arbitrary resource IDs.
5. Authorizes each nested ID through the initiating caller or a valid direct
   edge on the current frame. A nested target begins a new frame with its own
   independently revalidated edges.
6. Normalizes a single value, promise, async iterable, or `undefined`.
7. Parses every output when `outputSchema` is not null, emits `data`, and emits
   `done` automatically.
8. Records redacted facts as `done`, `error`, or `cancelled` in a `finally`
   block.

The audit detail contains resource ID, runtime, grant-lineage IDs, parent
invocation ID, binding resource IDs, timing, and result. It excludes input,
output, and external secret values. Caller cancellation and early iterator
return abort the complete nested call chain.

## HTTP server

`@rgap/server` exposes `RgapCommands` with Hono and
`@hono/zod-openapi`. Each route declaration defines runtime validation and the
OpenAPI contract.

The package generates:

- An OpenAPI 3.1 document.
- An interactive Swagger UI.
- A fetch-based TypeScript SDK with HeyAPI.
- Hono RPC types from the same chained route definitions.

`HttpRgapStore` implements `RgapStore` over that generated SDK and reconstructs
the same repository handles used by the local store.

Executable operations map one-to-one:

```text
GET    /resources/{id}/executable
PUT    /resources/{id}/executable     { runtime, bind? }
DELETE /resources/{id}/executable
POST   /resources/{id}/invoke         { input }
```

Invoke responds as `application/x-ndjson`, with one serialized `data` or
`done` event per line. Runtime failures fail the response stream. The server
obtains the first event before committing the response, propagates request
cancellation, and closes the runtime iterator when the client disconnects.
`HttpRgapStore` uses generated methods for JSON operations and a streaming
fetch reader for invocation.

## Documentation application

`@rgap/docs` is a Next.js application using Fumadocs and MDX. Content metadata
defines navigation order and sidebar groups. The application generates search,
tables of contents, syntax highlighting, theme controls, social images, and
LLM-readable Markdown routes from the same pages. `pnpm docs:dev` serves it on
port 3001 so the HTTP API can run beside it on port 3000.

## Scratchpad

`@rgap/examples` consumes `@rgap/sqlite` and `@rgap/core` like an external
TypeScript application. The secret-store app configures one trusted runtime
whose sealed input contains an externally stored credential resource ID and
another runtime that invokes it by resource ID. It creates the outer
executable through an ordinary delegated repository plane without granting
that plane authority over the credential.

Change only store construction to run the same walkthrough against HTTP:

```ts
const store = new HttpRgapStore({
  baseUrl: 'http://localhost:3000',
  adminToken: process.env.RGAP_ADMIN_TOKEN ?? 'test',
});
```

calls, and the HTTP store.

## Verification

`pnpm build` type-checks every workspace package and produces the documentation
site. `pnpm test` runs the core, SQLite, and server suites. Core's 100% coverage
threshold is a gate over its source rather than a report, and each downstream
package exercises its real adapter instead of a stand-in.
