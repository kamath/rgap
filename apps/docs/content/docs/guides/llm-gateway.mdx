title: Build an LLM proxy
description: Expose a streaming OpenAI-compatible proxy that gates access to approved models while keeping provider credentials private.
---

Expose a streaming OpenAI-compatible proxy that applications can use to call
approved models without receiving provider API keys. RGAP gates every request
to the models its caller can access and selects provider credentials only after
authorization succeeds.

RBAC and scoped grants support the proxy's access policies. Represent each
callable model as an executable resource, then grant a team, application, or
workload access to the complete catalog, one provider, or one model.

## Design the model hierarchy

Organize resources at the level where policy changes:

```text
models/
├── openai/
│   ├── gpt-5.6-sol
│   └── gpt-5.6-luna
└── anthropic/
    └── claude-sonnet
```

A grant on `models` covers the complete catalog. A grant on `models/openai`
covers that provider, and a grant on one model reaches only that model.
Resources keep stable IDs when names or catalog placement change.

## Register provider runtimes

Define the trusted runtime in the host with `fetch`. Provider credentials and
the base URL stay in deployment configuration:

```ts
const providerApiKey = process.env.OPENAI_API_KEY;
const providerBaseURL = new URL(
  process.env.OPENAI_BASE_URL ?? 'https://api.openai.com',
);

const openaiRuntime = {
  inputSchema: OpenAIInputSchema,
  outputSchema: z.unknown(),
  async invoke({ input, signal }) {
    const body = {
      ...input.body,
      model: input.model,
    };
    const response = await fetch(new URL(input.endpoint, providerBaseURL), {
      method: input.method,
      headers: {
        ...input.headers,
        'content-type': 'application/json',
        authorization: `Bearer ${providerApiKey}`,
      },
      body: JSON.stringify(body),
      signal,
    });
    return input.body.stream === true ? jsonSse(response) : response.json();
  },
} satisfies InvokeRuntime<OpenAIInput, unknown>;
```

The host reads `OPENAI_API_KEY` and `OPENAI_BASE_URL`. The runtime forwards the
resource's method, endpoint, and headers plus the caller's body, then applies the
separately sealed model after the caller-controlled body.

```ts
const chatCompletions = {
  method: 'POST',
  endpoint: '/v1/chat/completions',
} as const;

const model = await admin.resources.create({
  name: 'models/openai/gpt-5.6-sol',
  executable: {
    runtime: 'openai',
    input: {
      ...chatCompletions,
      headers: {},
      model: 'gpt-5.6-sol',
    },
  },
});
```

The sealed method, endpoint, headers, and model prevent a caller from redirecting
the credentialed request, replacing deployment-controlled headers, changing the
operation, or turning authority for one model into authority for another. The
caller supplies the remaining OpenAI body under `body`.

## Grant the smallest useful scope

Bind organizational grants to the appropriate catalog node:

```ts
const application = await admin.grants.create({
  name: 'company/product/search-service',
  bindings: [{
    id: model.id,
    permissions: ['invoke'],
  }],
  expiresAt: null,
});

const bearer = await application.tokens.create({
  label: 'production',
});
```

The grant path can mirror a company, team, service, environment, or workload.
Delegated child grants can shorten expiration or narrow model coverage, but
cannot add models or permissions outside their parent.

## Invoke through the gateway

The application resolves the model with its RGAP bearer and invokes its narrow
interface:

```ts
const plane = store.as(bearer.value);
const authorizedModel = await plane.resources.get(model.id);

for await (const event of authorizedModel.invoke({
  input: {
    messages: [{
      role: 'user',
      content: 'Summarize the incident report.',
    }],
  },
})) {
  console.log(event);
}
```

The same operation is available through
`POST /resources/{id}/invoke` on the [HTTP API](/docs/guides/http-api).

## Mount an OpenAI-compatible API

The host maps public model names to deployment-owned RGAP resource IDs. Its Hono
route removes `model` from the caller's body and invokes the mapped resource:

```ts
app.on(chatCompletions.method, chatCompletions.endpoint, async (context) => {
  const request = ChatRequestSchema.parse(await context.req.json());
  const { model, ...body } = request;
  const resource = models.get(model);
  const bearer = tokenValue(
    context.req.header('authorization').replace(/^Bearer\s+/i, ''),
  );
  const repository = store.as(bearer);
  const invocation = repository.invoke(resource.id, {
    input: {
      body,
    },
    signal: context.req.raw.signal,
  });
  // Write each invocation data event as an OpenAI response or SSE chunk.
});
```

The complete example performs request validation and error translation directly
in the route. The public route and executable share the same operation
descriptor, so the request invokes a resource parameterized for that method and
endpoint. The route reads the request bearer, selects `store.as(bearer)`,
authorizes `invoke` on the mapped model resource, and returns either the
provider's response object or server-sent events. The caller-supplied model name
selects only from the host's fixed map.

Existing OpenAI clients connect by setting the app's `/v1` URL as their base
URL and using an RGAP bearer as the API key.

Other operations use the same pattern. An image-generation resource seals
`POST /v1/images/generations`, its headers, and its approved model; the public
Hono route mounts that descriptor and invokes the selected resource. JSON
responses and JSON SSE streams use the same runtime.

## Apply policy at the right level

| Requirement | Resource and grant design |
| --- | --- |
| One approved model | Grant `invoke` on the model resource. |
| Every model from one provider | Grant `invoke` on the provider folder. |
| Separate staging and production | Use distinct grant branches and bearers. |
| Short-lived workload access | Delegate a child grant with an earlier expiration. |
| Immediate shutdown | Revoke the workload, service, team, or company ancestor. |

<Callout type="warn" title="Keep trusted fields out of caller input">
  Seal the provider, model, credential reference, and fixed safety configuration
  in the executable resource. Validate every caller-controlled field in the
  runtime.
</Callout>
