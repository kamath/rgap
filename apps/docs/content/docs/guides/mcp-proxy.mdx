---
title: OAuth MCP proxy
description: Connect an OAuth-protected MCP server, authorize it, and invoke its RPCs through RGAP.
---

`@rgap/mcp-proxy` provides a mountable Hono app and MCP runtime. This walkthrough
turns one authenticated Streamable HTTP connection into an executable RGAP
resource. RGAP authorizes the caller, while the proxy keeps the upstream OAuth
credentials and MCP session.

This guide connects a remote MCP endpoint, completes OAuth when the
server requires it, and sends `tools/list` and `tools/call` through the RGAP
authorized MCP proxy route.

## Before you start

Clone the repository and install its workspace dependencies:

```bash
pnpm install
```

Choose a remote Streamable HTTP MCP endpoint. The endpoint may allow anonymous
access or require the MCP OAuth authorization flow.

The gateway listens on port `3003`. Its OAuth redirect URI is:

```text
http://127.0.0.1:3003/oauth/callback
```

The authorization server must accept that callback URI. Use a public HTTPS
URL for a remote deployment. `PUBLIC_BASE_URL` is the externally visible URL
where the proxy app is mounted, including any path prefix.

## Compose the proxy

The MCP runtime exists before store construction so the deployment can
register it with its RGAP store. The proxy app uses that store internally
without mounting the generic RGAP HTTP API and can sit beneath any Hono route:

```ts title="examples/mcp-proxy/index.ts"
import { serve } from '@hono/node-server';
import {
  createMcpProxyApp,
  createMcpProxyRuntime,
  type McpCredential,
} from '@rgap/mcp-proxy';
import { SqliteCredentialStore } from '@rgap/local-credential-store';
import { SqliteOAuthFlowStore } from '@rgap/local-oauth-flow-store';
import { createApp as createRgapApp } from '@rgap/server';
import { SqliteRgapStore } from '@rgap/sqlite';
import { Hono } from 'hono';

const port = Number(process.env.PORT ?? 3003);
const publicBaseUrl = new URL(
  process.env.PUBLIC_BASE_URL ?? `http://127.0.0.1:${port}`,
);
const credentialStore = new SqliteCredentialStore<McpCredential>(
  'credentials.db',
);
const flowStore = new SqliteOAuthFlowStore('oauth-flows.db');
const mcp = createMcpProxyRuntime({
  publicBaseUrl,
  credentialStore,
  flowStore,
});
const store = new SqliteRgapStore({
  url: 'rgap.db',
  runtimes: { mcp: mcp.runtime },
});

const app = new Hono();
app.route('/', createMcpProxyApp({ mcp, store }));
app.route('/rgap', createRgapApp({
  store,
  adminToken: process.env.RGAP_ADMIN_TOKEN ?? 'test',
}));

serve({ fetch: app.fetch, port });
```

The app exposes `POST /mcp/:connectionId`, `GET /oauth/callback`, and
`GET /oauth/client-metadata.json` relative to its mount point. It does not
expose generic RGAP routes. The MCP route extracts the RGAP bearer, opens the
guarded repository with `store.as(token)`, and invokes the fixed connection ID
from the route. RGAP therefore authorizes each forwarded MCP request.

The package derives OAuth URLs by appending their paths to `publicBaseUrl`. The
public URL and Hono mount path must identify the same route. The caller owns all
injected stores and calls `mcp.close()` before closing them.

The `/rgap` mount remains an ordinary `@rgap/server` app. Applications use it
to manage server, credential, and executable connection resources. The MCP
proxy does not call those HTTP routes; it calls the shared `RgapStore` directly,
so no loopback request or administrative bearer crosses between route groups.

## 1. Start the proxy

Run the example from the repository root:

```bash
MCP_SERVER_URL=https://server.smithery.ai/gmail \
PUBLIC_BASE_URL=http://127.0.0.1:3003 \
pnpm --filter @rgap/examples mcp-proxy
```

The app prints:

```text
MCP proxy listening on http://localhost:3003
Upstream MCP server resource: <server-resource-id>
Executable MCP connection: <connection-resource-id>
RGAP bearer written to examples/mcp-proxy/invoker.token
```

The proxy creates this resource structure:

```text
acme/mcp/
├── servers/<server>
├── connections/<server>-default
└── credentials/<server>-default
```

The executable connection seals the upstream URL and binds the server and
credential resources. The generated grant contains `invoke` on the connection,
and `invoker.token` contains its opaque bearer.

## 2. Choose client registration

When `PUBLIC_BASE_URL` uses a public HTTPS origin, the proxy publishes:

```text
https://proxy.example.com/oauth/client-metadata.json
```

That document is the OAuth client ID. It contains the fixed callback URI,
client name, authorization-code grant, refresh-token grant, and public-client
token authentication method. The MCP SDK selects it when the authorization
server advertises Client ID Metadata Document support.

An HTTP loopback URL does not enable the metadata document because a Client ID
Metadata Document must have a public HTTPS URL with a path. The MCP SDK uses
dynamic client registration when the authorization server advertises a
registration endpoint.

To exercise Client ID Metadata Documents, expose the app through HTTPS and set
the matching public origin:

```bash
MCP_SERVER_URL=https://server.smithery.ai/gmail \
PUBLIC_BASE_URL=https://proxy.example.com \
pnpm --filter @rgap/examples mcp-proxy
```

The metadata URL and every value in its document derive from the same public
base URL, including its mount path, so `client_id` and `redirect_uri`
comparisons are exact.

## 3. Complete OAuth

When the MCP server requires OAuth, the app also prints:

```text
Authorize the MCP connection: https://authorization.example.com/authorize?...
```

Open that URL in a browser and approve access. The authorization server returns
the browser to the Hono callback. The callback:

1. Hashes the returned state and locates the pending flow in local storage.
2. Atomically marks the state as consumed.
3. Rejects expired or previously consumed flows.
4. Compares the returned state with the value bound to the credential.
5. Gives the callback parameters to the MCP SDK.
6. Lets the SDK validate the issuer and exchange the authorization code.
7. Stores the resulting tokens and reconnects to the MCP server.

The page displays `MCP authorization complete` when the connection succeeds.

The proxy stores OAuth tokens, client registration, discovery state, and PKCE
data in `examples/mcp-proxy/credentials.db`. The records are keyed by the RGAP
credential resource ID. Credential values never enter RGAP invocation input,
output, or audit records.

The callback state index uses the `OAuthFlowStore` interface from
`@rgap/local-oauth-flow-store`:

```ts
interface OAuthFlowStore {
  register(state: string, flow: OAuthFlowRecord): Promise<void>;
  claim(state: string, now?: Date): Promise<OAuthFlowRecord>;
  complete(state: string): Promise<void>;
  close(): Promise<void>;
}
```

The example constructs `SqliteOAuthFlowStore` from the same package and stores
the index in `examples/mcp-proxy/oauth-flows.db`. It hashes callback state
values with SHA-256 before using them as keys and atomically permits one claim
before the flow expires. Each record identifies the credential, MCP server,
internal flow, expiration, and one-time claim.

The interface keeps storage-specific concurrency inside each implementation.
A deployed proxy can supply a Redis, PostgreSQL, or other shared implementation
without changing callback routing. All proxy replicas share both the flow store
and the credential store. The callback restores the pending MCP connection from
the credential store before it gives the callback parameters to the MCP SDK, so
the process that receives the callback does not need to be the process that
started authorization.

<Callout type="warn" title="Local storage only">
  The SQLite credential adapter contains plaintext values. Use an
  encrypted deployment-owned credential store and a shared OAuth flow store for
  a deployed proxy.
</Callout>

## 4. Initialize an MCP client

Create an MCP SDK client for the executable connection ID printed by the app.
Set `RGAP_TOKEN` to the generated bearer and `MCP_CONNECTION_ID` to that ID.
The RGAP bearer is the proxy's incoming access token:

```ts title="client.ts"
import { createMcpProxyClient } from '@rgap/mcp-proxy-client';
import { z } from 'zod';

const token = process.env.RGAP_TOKEN!;
const connectionId = process.env.MCP_CONNECTION_ID!;
const client = await createMcpProxyClient({
  proxyUrl: new URL('http://localhost:3003'),
  connectionId,
  rgapToken: token,
  clientInfo: {
    name: 'rgap-walkthrough',
    version: '0.0.0',
  },
});
```

The repository includes that client in `examples/mcp-proxy/client.ts`. Run it
after completing the Smithery Gmail OAuth flow:

```bash
RGAP_TOKEN="$(<examples/mcp-proxy/invoker.token)" \
MCP_CONNECTION_ID=<connection-resource-id> \
pnpm --filter @rgap/examples exec tsx mcp-proxy/client.ts
```

`createMcpProxyClient` constructs the Streamable HTTP transport, attaches the
RGAP bearer, sends `initialize` and the initialized notification, and returns
the connected MCP SDK client. The proxy handles that lifecycle locally and
advertises request-response capabilities only. It does not forward lifecycle
messages through RGAP and does not open an SSE channel.

List the upstream tools through the initialized client:

```ts
const tools = await client.request(
  { method: 'tools/list', params: {} },
  z.unknown(),
);
console.log(tools);
```

RGAP validates `invoke` before the runtime resolves the credential binding or
sends the MCP request.

## 5. Call a tool

Use a tool name and arguments returned by `tools/list`:

```ts
const result = await client.request(
  {
    method: 'tools/call',
    params: {
      name: 'example_tool',
      arguments: {
        query: 'authorization',
      },
    },
  },
  z.unknown(),
);
console.log(result);

await client.close();
```

The connection accepts every client-to-server request supported by the
negotiated MCP protocol. Change `method` and `params` to invoke prompts,
resources, completion, or extension methods exposed by the server.

The MCP SDK owns `initialize`, `server/discover`, protocol negotiation, and
session lifecycle. Callers do not send those lifecycle requests through RGAP.

## 6. Understand the authorization boundary

The generated grant reaches the complete connection:

```yaml
resources:
  - id: <connection-resource-id>
    permissions: [invoke]
```

That authority intentionally covers the complete authenticated MCP server. The
caller receives the RGAP bearer but never receives an upstream access token,
refresh token, registered client secret, or PKCE verifier.

To downscope authority, synchronize discovered operations into child resources:

```text
acme/mcp/connections/<connection>/
├── tools/
│   ├── search
│   └── create_issue
├── prompts/
│   └── review
└── resources/
    └── repository
```

Each child seals its MCP method and operation name. A grant on one child then
authorizes that operation without authorizing the complete connection or its
siblings.

## 7. Restart the example

The RGAP database and credential database persist in
`examples/mcp-proxy`. Starting the example with the same MCP URL finds the
stable resources and reuses stored OAuth state. The app creates a fresh RGAP
invoker grant and overwrites `invoker.token` with its bearer.

Delete the local databases and bearer when you want a clean run:

```bash
rm -f \
  examples/mcp-proxy/credentials.db \
  examples/mcp-proxy/oauth-flows.db \
  examples/mcp-proxy/rgap.db \
  examples/mcp-proxy/invoker.token
```

## Deployment checks

The example receives its MCP URL from trusted deployment configuration. A
service that accepts user-supplied URLs also:

- permits HTTPS endpoints and explicitly configured loopback development URLs;
- blocks private, loopback, and link-local destinations by default;
- revalidates every redirect and DNS resolution;
- applies connection, request, and response-size limits;
- rate-limits callback failures and never logs callback query parameters;
- replaces the SQLite credential store with encrypted secret storage;
- replaces the local OAuth flow store with an implementation shared by every
  proxy replica; and
- places the RGAP administrative bearer behind an infrastructure boundary.

Continue with [MCP and agent examples](/docs/examples) for the resource and
delegation model, or [HTTP API](/docs/guides/http-api) for the complete RGAP
command surface.
